## 3. Do #714/#716/#720 close the hole they claim? (required check 3)

The guard is `scripts/evidence_index.py:137-166`. Two state transitions are forbidden:

**A (#716, 2120445): `{durable receipt has live id L} → {new receipt omits L or carries L non-live} → write`.** Before the fix, a doctor-only `refresh-static` receipt (zero runtime rows) overwrote the durable receipt, discarding the settlements. Proved by `tests/test_evidence_durability.py:589-634::test_refresh_static_refuses_when_prior_live_rows_cannot_be_reobserved`: it copies the checked-in omp receipt, drives `refresh-static --host omp` with a static doctor stub, asserts `REFUSING`, asserts `PSTACK_RUN_OMP_LIVE=1` in the message, and asserts the durable bytes are unchanged.

**B (#720, 1002590): `{durable has live id L} → {new receipt carries the same id with a non-live, non-PASS row} → write`.** The #716 check only looked for missing ids; a same-id `FAIL`/`BLOCKED` static row slipped through. Now the check is `sid not in current_by_id or not _is_preservable_settlement(current_by_id[sid])` (`:150-157`), so a same-id row that is not `observed_live`+`PASS`+typed-settlement (`scripts/portability_types.py:560-571`) is refused. ## Findings

### BLOCKER 1 — a genuine live regression can never be recorded

`scripts/evidence_index.py:150-166` refuses any write in which a prior live id is not re-observed live. The live driver reports failure as `evidence_level="offline"` (`scripts/drivers/omp.py:427`, `:536`, `:714`, `:808`) with verdict `FAIL`/`BLOCKED`, and `_is_preservable_settlement` requires `evidence_level == "observed_live"` and `verdict == "PASS"` (`scripts/portability_types.py:560-571`). So a `run --host omp` that observes a real spawn/cancel/isolation regression lands in exactly the state the guard refuses, and exits before `evidence_index.py:174` writes. The durable receipt (`~/.audit/evidence/omp-receipt.json`, tracked) keeps the previous live PASS; `check-evidence` (`evidence_index.py:242-297`), `check-staleness-action` (`:299`), `derive_support_state` (`scripts/evidence_durability.py:96`) and the offline test `tests/test_evidence_durability.py:49-106` all keep reading it. The regression is observable only in `sys.exit`'s message and in a gitignored run-dir receipt. `tests/test_evidence_settlement.py:333-344` codifies this: it drives a failing receipt, asserts `REFUSING`, and asserts `durable_file.read_bytes() == durable_before`, i.e. the failure is never persisted. Net effect: the evidence system cannot record bad news, which contradicts the whole point of a durable receipt.

The guard cannot distinguish "static refresh that proved nothing" from "live run that proved a failure" because that distinction is carried only by `evidence_level`, and the driver collapses live-attempted-but-failed into `offline`. The code-judo move is to stop inferring provenance from a verdict-adjacent enum: record the gate decision on the receipt (e.g. `live_attempted: true` from `PSTACK_RUN_OMP_LIVE`, or a third scenario level `observed_live_failed` emitted by `_child_spawn_live`/`_child_cancel_live`/`_isolation_live` failure returns), and scope the refusal to receipts where the live gate was not attempted. Then a live `FAIL` overwrites and a static row still cannot. Behavior pin: the two forbidden transitions above must keep refusing (tests at `test_evidence_durability.py:589` and `test_evidence_index_resilience.py:361`), and a new test must prove the live-failure shape (`offline`/`observed_live_failed` + `FAIL`) does overwrite. Consumers to keep green: `check_evidence_action`, `check_staleness_action`, `derive_support_state`, `test_durable_receipts_exist_for_all_five_hosts`, `test_omp_profile_claims_only_what_its_receipt_settles`.

### BLOCKER 2 — the canonical row now claims PASS over recorded drift, with no field to carry the drift

See §2. PR #718's `scenarios[0].stdout_snippet` in all five receipts reads `Freshness: DRIFT (34 commits ahead)` while `verdict: PASS`, `planes.canonical: PASS`, and `surface_revisions.upstream_head` stays equal to `canonical_pin` (88d47514…). `openspec/canonical-inventory.json` is unchanged by the PR and still says `CURRENT`/`0`. Because `scripts/surface_revisions.py:287-299` reads the inventory file rather than observing, and `evaluate_plane_staleness` compares file-derived fields, drift is structurally invisible to every consumer that reads JSON. A reader of `index.json` sees a canonical PASS with revision data claiming up-to-date. Remedy: add `upstream_freshness`/`commits_ahead` (or the observed upstream head) to `SurfaceRevisions`, compute it next to `canonical_pin`, and either fail canonical or record it `UNTESTED` on `DRIFT`; regenerate the inventory in the same change. Behavior pin: gaps=0 must still be `pin_conformance: PASS`.

### BLOCKER 3 — a no-op check is recorded as a plane PASS (the PR #718 meaning change)

`scripts/verify-portable.py:252-262` appends `doctor-openspec-validation` with `verdict="PASS"` and text that says nothing was validated; PR #718's restamp is what promoted it into every durable receipt. `settle_planes` counts it. The receipt now contains a row whose description contradicts its verdict, and that row is the only remaining evidence that the canonical plane's OpenSpec half was ever checked. Cheapest correct fix: delete the `state == "none"` branch and append no row — the canonical plane still reduces to PASS from the real `doctor-canonical-index` row, so behavior is identical and one false PASS disappears. The schema has no "not applicable" verdict, so this is preferred over inventing one. Delete the PASS assertion at `tests/test_verify_portable.py:305-311` and the `state == "none"` expectations that depend on it.

### MAJOR 4 — the guard is not atomic w.r.t. the bytes it protects

`scripts/evidence_index.py:174` writes the durable receipt with `durable_file.write_text(...)`, and line 178 writes `index.json` the same way. Both truncate in place. A crash, full disk, or SIGKILL between truncate and flush destroys the only tracked live settlement — the exact loss #714/#716/#720 exist to prevent. Remedy is one line each: write `durable_file.with_suffix(".tmp")` then `os.replace(...)`; same for the index. Then the guard's invariant ("never lose a live row") holds under interruption, not only under a well-formed receipt.

### MAJOR 5 — a refused durable write still exits 0

`scripts/evidence_index.py:139-148`: an unreadable/corrupt durable receipt sets `reusable = False`, prints `REFUSING to overwrite ...`, and then falls through to line 184's `Evidence captured at ...` and `return receipt_file`. `scripts/verify-portable.py:536` ignores the return value and `main()` exits on `all_pass` (`:571`), which the failed persistence never touched. `tests/test_evidence_settlement.py:345-362` asserts the bytes are untouched but never asserts a non-zero exit code, so the hole is pinned as correct. A `run --host omp` can therefore exit 0 while persisting nothing. Remedy: `sys.exit` on the refusal path like the sibling branches, or return an error and `and` it into `all_pass`; add the exit-code assertion to that test.

### MAJOR 6 — preserved live rows are re-dated by the receipt that copies them, and the index hides provenance

`scripts/evidence_durability.py:44-58` copies the prior scenario with `preserved_from=<run_id>` and nothing else: no observation timestamp, no surface revisions of the observing run. The receipt that receives it has `run_id`/`timestamp` of the refresh (`scripts/verify-portable.py:445`). `evidence_index_row` (`scripts/evidence_index.py:54-63`) projects only `receipt/run_id/timestamp/overall_verdict/planes/surface_revisions`, so `.audit/evidence/index.json` publishes a fresh timestamp and a fresh run id next to `runtime: PASS` with no access to `preserved_from`. `tests/test_evidence_index_resilience.py:171-187` is named `test_repeated_refreshes_keep_the_run_that_observed`, yet asserts `second_durable["run_id"] == second_receipt.run_id` — the non-observing run. Remedy: carry `observed_at`/`observed_run_id` (from the preserved row) and project them into the index row; a consumer asking "when was this observed" must not get the refresh time. Until then, requirement 1's "recorded run/timestamp" is only true by luck: PR #718 re-ran live, but the next static refresh of omp will publish old settlements under a new timestamp.

### MAJOR 7 — the tool's own remedy cannot run

`scripts/evidence_index.py:198-200` ("Rebuild it with: `python3 scripts/verify-portable.py refresh-static --host all`") and `:221-231` ("Rebuild the row with: ... `refresh-static --host all`") tell the operator to run a command that, since #714, always aborts on omp: `refresh-static` builds a doctor-only receipt, `dropped` is non-empty for any host with live rows, and the writer exits at `:158`. `tests/test_evidence_index_resilience.py:272-295` asserts the `--host all` message and then deliberately rebuilds with `--host grok`, which is the tell. Remedy: the index rebuild is a read, not a rewrite — let `refresh-static` (or a dedicated `rebuild-index`) repopulate `index.json` from durable receipts without re-running any host receipt; keep `--host all` for hosts without live rows and name the live gate for omp in the message.

### MAJOR 8 — the guard's tests never exercise the shape the live driver emits

Both forbidden-overwrite tests build same-id rows with `evidence_level="static"` (`tests/evidence_test_helpers.py:281-298`, `_proof_bar_refresh` at `:296`), while production live failures emit `evidence_level="offline"` (`scripts/drivers/omp.py:427`, `:536`, `:714`, `:808`). No test constructs offline+`FAIL` for the guard, so its behavior on the real failure shape is unproven; combined with BLOCKER 1 it is the whole bug. Also, `tests/test_evidence_durability.py:589-634` copies the checked-in omp receipt and asserts `live_ids` is non-empty — the offline CI gate now depends on mutable audit data, duplicating the synthetic test at `test_evidence_index_resilience.py:361` while proving nothing extra. Remedy: parameterize `_omp_spawn_scenario` over `("static", "offline")` in the guard tests and delete the file-copy variant in favour of `_omp_live_root`.

### MAJOR 9 — offline CI asserts the live claim instead of verifying it

`tests/test_evidence_durability.py:49-106` hard-codes `{runtime-child-spawn-omp, runtime-child-cancel-omp, runtime-isolation-omp}`, `overall_verdict == PASS` and the four-plane PASS map for the checked-in omp receipt, and `profiles/omp.json` pins `agent.spawn`/`agent.join`/`agent.cancel`/`workspace.isolated` as `verified` into it. The only way to honestly downgrade therefore includes editing this tracked test, deleting a tracked receipt, and re-pinning four capabilities. Combined with BLOCKER 1 (the guard refuses the downgrade) the claim is effectively immutable. `portability-offline.yml:64-69` says the behaviour is not covered, so the green job asserts nothing about the claim it enforces. Remedy: keep a shape assertion (receipt parses, validates, index agrees) and move the "exactly these three live ids" expectation into a synthetic fixture; let profile pins degrade to `static-only` when the receipt's runtime plane is not PASS.

### MINOR 10 — duplicate validation in the wrong layer

`HarnessProfile` is constructed field-by-field in `scripts/evidence_index.py:260-277` and again — as a generated `python -c` string roughly 500 characters long — in `scripts/verify-portable.py:331`, which is then copied into every `doctor-profile-<host>` receipt row. Three more copies live in tests (`tests/test_evidence_durability.py:109-141`, `tests/evidence_test_helpers.py:34-48` and `:250-267`). `tests/test_evidence_durability.py:88-93` re-implements `index_row_mismatch`'s four-field comparison (`scripts/evidence_index.py:233-239`) inside the test, so a regression in the production comparison stays green. Remedy: add `HarnessProfile.load(path)`; `evidence_index.check_evidence_action`, the doctor command, and the three test loaders call it. Removes the 500-char command string and one duplicate invariant. Sizes for the record: `scripts/evidence_index.py` 379, `scripts/evidence_durability.py` 248, `scripts/verify-portable.py` 576, `scripts/drivers/omp.py` 823, `tests/test_evidence_durability.py` 634, `tests/test_evidence_settlement.py` 757, `tests/test_evidence_index_resilience.py` 373, `tests/evidence_test_helpers.py` 362. No file crosses 1000 lines and no diff crosses it; the lane is ~627 production lines to ~2,126 test lines plus 362 helper lines, which is where the duplicated invariants come from.

### MINOR 11 — a self-referential runtime PASS row

`scripts/drivers/omp.py:804-823` (`runtime-evidence-capture-omp`) emits `verdict: PASS` from `test -f .audit/evidence/omp-receipt.json`, i.e. the row passes because the writer is about to create the file containing it. It is `plane: runtime`, `evidence_level: offline`, so it cannot satisfy `_is_observed_settlement`, but it does inflate the runtime plane with a tautology. Delete it, or move it to a `package`/`receipt` plane where existence is the actual claim.

### MINOR 12 — recorded commands are not replayable records

All `observed_live` rows carry prose commands (parenthetical `->` descriptions) rather than the invocation that produced them; `runtime-isolation-omp` additionally names a `/tmp/omp-iso-live-*/isolation.yml` that `_isolation_live` deletes (`scripts/drivers/omp.py:701`). The reproduction exists only as `PSTACK_RUN_OMP_LIVE=1 python3 scripts/verify-portable.py run --host omp`, which appears in the refusal message and in `docs/verification-test-tiers.md` but not in the row. Remedy: record the driver invocation in `command` and put the generated config text in the row's evidence (or the run-dir receipt, tracked) so the observation is reconstructible from the record.
