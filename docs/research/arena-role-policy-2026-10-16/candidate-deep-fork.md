# Candidate D3 — host-per-adapter deep fork

Each harness owns its **own modeled role table and its own runtime conventions**, generated by an
**adapter-local generator** whose structure is taken from `pstack-claude/tools/runtimes.mjs`'s
declarative row registry plus that port's Pi mechanism patterns (extension/hook conventions),
adopted wholesale per adapter. `pstack.package.json#/roles` keeps the canonical IDs; it is no longer
the shape every host table is squeezed into.

## The strongest honest case: the divergence is already deep, and already forked

D3 is not a strawman; it is the honest description of what the tree does today, only untidy.

1. **The fork is by mechanism phase, not by value.** `profiles/droid.json.runtime_conventions`
   forbids `model` and `reasoning_effort` on the spawn primitive, and the droid generator hardcodes
   `model: inherit` (`scripts/project-package.py:330`). Role→model binding is therefore
   *definition-time* for droid, *projection-time* for codex/antigravity (`generate_codex_models`,
   `generate_antigravity_models` — checked-in host model files), and *dispatch-time* for
   grok/omp/opencode (`allowed_spawn_fields` include `model`/`role`). One shared `modelChoices`
   shape must union three phases and then be re-interpreted per host anyway.
2. **The tables are already natively different shapes.** codex/antigravity: `singleRoleDefault` +
   `panel` + `available[]` + `roles[]`. droid: no table at all, tool-restriction frontmatter
   instead. omp/opencode: `default_model` is `"pi"` / `"opencode"` — aggregate tokens, not slugs;
   codex's is a slug (`gpt-6.1-sol`). Twelve per-host generator functions already sit in the shared
   projector (6 manifest generators in `TARGET_MAP`, plus 6 host-specific model/role/marketplace
   emitters).
3. **The existing fork already drifted — measurably.** Canonical registry: 22 kebab-case role IDs.
   The two hand-written per-host tables in the *shared* generator use space-separated display
   labels with **zero** exact intersection with those IDs, 15 non-canonical label strings each, and
   15 (codex) / 17 (antigravity) canonical roles absent entirely (`comment-sicko`, `how-critics`,
   `poteto-agent`, `independent-verifier` …). Wholesale adoption of the comparator's row registry is
   the closest thing to "model it per host instead of pretending one shape fits".

## (a) Data shape

`adapters/<host>/` — host-owned, one directory per adapter, no cross-host document:

```
roles.json        { adapter_version, host,
                    role_source: "pstack.package.json#/roles",   # provenance only, not schema
                    roles: { <host-native label>: { models|panel|single, effort?,
                             skill, mechanism: spawn-field|projection-file|definition-frontmatter,
                             evidence_ref } } }                  # key namespace is host-owned
conventions.json  runtime_conventions (verbatim, as today) + mechanism + generator entrypoint
                  + receipt path + fixture paths
generate.py       imports roles.json/conventions.json, emits ONLY this host's native artifacts
                  (codex/antigravity model file, droid role frontmatter, omp/opencode manifest)
fixtures/         host-local negative fixtures (droid: model/effort forbidden; catalog miss; …)
```

No shared schema constrains `roles.json` keys. Each adapter validates its own projections with its
own `--check` and its own fixtures. Host model facts stay in `profiles/<host>.json` unchanged.

## (b) Boundary / ownership

| Artifact | Owner | Must not own |
| --- | --- | --- |
| Canonical role IDs, tiers, descriptions | `pstack.package.json#/roles` (unchanged) | host defaults |
| Host role table | the adapter's `roles.json` | another adapter's labels or catalog |
| Host model facts / runtime conventions | `profiles/<host>.json` (runtime-observed) | global policy |
| Projection generator | adapter-local generator, sole writer of that host's projections | other hosts' manifests |
| Mechanism + fixtures + receipts | adapter directory | aggregate/cross-host PASS claims |
| Domain overlay | qstack, post-router (unchanged) | a pstack router or model namespace |

## (c) Why it is minimal

Zero new schemas, resolvers, control planes, schedulers, gateways or stores: a directory per
adapter, and the twelve generator functions already in `TARGET_MAP` promoted into adapter-local
modules. Host config keeps living in `profiles/<host>.json`. Conceptually the *smallest* surface on
offer — no shared invariant code, no union types, no cross-host arbitration — and the first
increment is provably behavior-preserving: move `generate_codex_models` / `generate_antigravity_models`
bodies into `adapters/<host>/roles.json` byte-for-byte, then confirm `project-package.py --check`
is unchanged. Cost is artifact count, not concept count.

## (d) What it rejects, and why

- **One shared `model-role-policy.json` with `hosts.<host>.{model_catalog, tier_defaults, role_overrides}`
  sections** (the typed seam). Rejected because it forces one shape over three binding phases and
  two label conventions; the only thing it uniquely buys is canonical key agreement, which D3 buys
  with a derived check instead.
- **A provider-independent agent-runtime gateway/DSL.** Second control plane; duplicates the router
  and the host auth/isolation model; YAGNI.
- **Prose-only mapping (no-change control).** Cheap, but model drift stays untestable.
- **Copying the comparator wholesale, state included.** Its `~/.claude` orchestrate store is already
  closed as undesired (#402); a durable store is out of bounds for every candidate.

## Honest cost: drift and provenance

- **C1 — N authorities for role IDs.** This is D3's real bill, and it is already being paid: 15/22
  canonical roles are missing from the codex table today. Unmitigated, adding one canonical role
  costs N edits with no gate that fails. The only honest mitigation — a derived CI check that each
  adapter table's canonical-key projection equals the package key set, plus `role_source` recorded
  verbatim — **re-imports the single-authority invariant the pure fork drops**. The defensible D3 is
  therefore *adapter-owned tables + canonically-derived key gate*, not a genuine authority fork.
- **C5 — provenance.** "Wholesale" imports the comparator's own declaration: `tools/forks.json`
  at `94f5ce9` lists 48 policy forks, all `review_state=pending`
  (`docs/research/pstack-claude-forks-2026-10-15.json`), and both the existing design's Arena row
  and issue #434 make importing them a blocked, review-first action. Importing *structure* (a
  declarative row registry) is defensible; importing its tables, model aliases, hooks or state is
  the policy-fork import the rubric forbids.
- **C3 caveat inside its own strongest column.** Pi ≠ OMP: `profiles/omp.json` exposes no Pi
  extension primitive, and the existing design states plainly that an observed Pi extension feature
  proves nothing about OMP. "Pi mechanisms as OMP's conventions" is an unverified host assertion,
  not host-native correctness.
- **C2 — matrix maintenance.** 6 profiles × 22 roles, N generators, no shared validation: panel-seat
  or diversity semantics can diverge across hosts with nothing failing unless each adapter
  re-declares its own fixture.
- **C4 — evidence.** Per-adapter fixtures are deterministic and fail-closed per host, but there is no
  shared negative-fixture harness and a green adapter generator is static proof only; a runtime
  receipt per host is still required, and no aggregate claim is valid.

Verdict: D3 wins host-native correctness outright and is the truthful description of the current
de-facto layout, but it loses fidelity and boundary safety in proportion to how literally "fork"
is taken, and its own mitigations converge on the typed seam it rejects.
