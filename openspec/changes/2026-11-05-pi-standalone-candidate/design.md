# Design: standalone Pi candidate, without a seventh runtime

Status: DESIGN / static-only. Issue #896 owns implementation.

## Ownership graph

~~~text
official Cursor PStack canonical intent (UPSTREAM pin)
              |
tommy-ca/pstack canonical skills and 17 capability contracts
              |
        host-owned profile selector
              |
standalone Pi (candidate, distinct from OMP)
    |         |          |
 native Pi  pi-subagents  pi-better-sandbox
    |         |          |
 skills/MCP  delegates   sandbox tool admission
 sessions    child IDs   OS kernel, configured per actor
    |
 optional pi-web-access (researcher tools only)
              |
       existing PStack verification & evidence contracts
              |
         existing project .llm-wiki
~~~

Native Pi owns tool/MCP exposure, codemode, model/catalog, sessions and parent agent-loop. Delegation extension owns child runs and worktrees. Sandbox extension owns admitted task operations but is not privileged against malicious runtime extensions, inherited secrets or remote SSH. CI, not the LLM, owns acceptance.

## Candidate profile identity

Existing scripts/host_identity.py intentionally fixes six **built-in** hosts and allows namespace-qualified external/candidate IDs. It also reserves bare pi, and external IDs contain a colon that is invalid in Windows filenames. Therefore **do not** create profiles/pi.json or repurpose profiles/omp.json as a shortcut. Issue #896 must decide a reversible path-safe candidate identity-to-filename encoding and validate it across portability_types, schemas and package projection. Candidate enrollment MUST keep support_state candidate and every unproven binding static-only/unverified. Promotion requires native adapter test/receipts before adding any built-in host.

## Data contracts

Use existing Binding and HarnessProfile classes, not a duplicate schema:

~~~text
Binding {
  host, capability, implementation_status,
  primitive?, enforcement, verification_status,
  evidence_ref?, notes?
}
~~~

Allowed classifications and receipt promotion rules are defined by scripts/portability_types.py and scripts/evidence_durability.py. Add no new enum value for extension unless schema demands one; classify a package-backed operation as shim/version-gated and name the external package/version in primitive/notes, reserving native for true host-owned behavior.

Example evidence:
- Package readme claims steering → static-only.
- Foreground child completion with identity and transcript → observed_live for agent.spawn + agent.join only.
- Cancellation with terminal cancelled → observed_live for agent.cancel only.
- Parent resume → no implication of resumed child.
- A worktree path → no implication of kernel sandboxing.
- Two child IDs on one LLM family → independent process lanes, **not** independent model families.

## Child lifecycle and failure behavior

~~~text
Intent + acceptance
  -> parent selects exact known role/model/tools
  -> permission/admission check; fail closed on absent control
  -> spawn child through one pi-subagents owner
  -> stream/monitor identifiable run
  -> settle join OR cancel OR timeout
  -> report source outputs, terminal state, worktree diff
  -> deterministic verification and receipt
  -> independent diff/security/quality review
  -> integration only if acceptance gates pass
~~~

Timeout, refusal, missing model slug, canceled child, stale evidence or sandbox tool denial MUST NEVER be silently converted to PASS. Enforce concurrency/depth/budget using documented extension controls and test implementation behavior rather than inferred defaults.

## Verification/skills and formal contract

Functional driver must reuse scripts/verify_portable.py and a host-native create-verification-skill artifact. It must prove actual Pi CLI and subagent flows and provide the existing four-plane receipt. Formal skill must cover code-linked authorization and state-transition invariants with a deliberate failing mutant. Existing tools stay canonical. A separate LLM judge may provide findings but is not independent deterministic evidence.

## LLMWiki policy

Keep .llm-wiki/raw/sources write-once via scripts/llm_wiki.py ingest and .llm-wiki/index.md generated by scripts/llm_wiki.py index --write. This additive spec may add curated candidate analyses, but MUST NOT claim locally ingested immutable raw source revisions until the ingest command has run and the digest log is present. Re-run wiki check, source verify and graph checks before promotion.

## Rollback

Candidate spec removal leaves all existing six host profiles, runtime drivers, package projection, PStack skills and compiled wiki sources intact. No automatic upgrades or user-installed npm package removal.
